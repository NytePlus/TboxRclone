## 已落实的两个优化

1. **单文件故障用例定向核验并自动编排。** `finder-inspect --file RELATIVE_FILE ROOT` 直接从云 API 完整读取目标文件，仍计算 SHA-256，不经过 WebDAV。历史三轮全目录分别读取8/25/29个文件、约27/99/117 MiB；目标始终只有9 MiB。新流程并行生成审阅图与云端读取，云端成功后自动执行源文件/挂载/云端比较。每阶段及整体记录耗时、退出码；失败不产出 UI PASS。目录和树用例继续用完整 inventory，定向结果不能作为目录存在性/无额外文件的证明。
2. **直接生成实际审阅像素尺寸。** Swift 原来通过 Retina NSImage 生成2560×4500，再调用sips缩到1280×2250；现直接生成1280×2250，保留每秒一帧、每张10帧和全部屏幕。新增完整采样索引。没有降低采样频率或跳过静止尾部。

## 后续实测：避免窗口遮挡导致整段录制作废

ST-015-F/finder-forbidden-20261114-0212 在拖放前发现目标落点被源窗口遮挡，未发送鼠标事件；原流程仍等完整45秒录制结束。该失败证据保留。

record.sh 现在在录制前运行已有 CHECK_ONLY 检查：若失败，仅重排这两个测试窗口一次并复检。实际拖拽前仍会再次检查，未放宽遮挡判据。0215 轮的首次检查发现遮挡，重排后通过，预检查阶段共2.959秒，随后成功触发403。重复失败会在录制前退出。drag.swift 将这种可预期拒绝改为退出码2，避免 fatalError 的崩溃堆栈与系统崩溃报告开销。

这项优化降低无效录制返工，不改变录像时长或验收要求。
