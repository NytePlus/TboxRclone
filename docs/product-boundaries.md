# 产品功能边界

本文说明当前版本能安全承诺的范围。系统测试结果见[验证规格](verification.md)，接口细节见 [API 约束](api.md)和 [rclone/WebDAV 契约](rclone-webdav.md)。

## 使用模型

- 一个云盘空间由一个受控 TboxRclone 服务实例使用；挂载或恢复未完成期间，不支持网页端、官方客户端、另一台电脑或其他协作者同时修改同一挂载根。
- 同一路径操作由用户顺序执行。不同文件和同一上传的不同分片可以并行。
- 本地锁和 journal 不能提供跨客户端、跨主机的分布式锁；发现身份或内容变化时会拒绝继续，但不承诺防止外部客户端造成的丢失更新。
- 服务与恢复命令必须共用同一 `state_dir` 和所有权注册目录。不得通过更换目录、删除注册文件或复制状态来绕过未决操作。

完整并发契约见[单读写客户端与恢复约束](concurrency-contract.md)。

## 写入与恢复

- 写入默认关闭。仅在明确配置 `lab_writes=true` 的隔离远端启用实验写入。
- 输入先进入受 journal 管理的 spool，再初始化分片会话、上传、confirm，并独立读取云端完整内容核对 SHA-256。
- `DurableFileSpool` 保存输入副本；`SourceFileSpool` 只保存源路径和身份信息，每次打开或恢复都会重新核对设备号、inode、大小、mtime 和 SHA-256。源文件缺失、被替换或内容变化时拒绝继续。
- `SourceFileSpool` 的源文件归调用方所有。TboxRclone 不会在云端 confirm 和独立内容核对完成前删除源文件，也不会替调用方自动删除源文件。
- 失败、结果未知和未完成操作会保留 journal 与 spool。恢复是显式操作，不承诺 Finder 自动继续。
- 默认单次上传上限为 2 GiB，总 spool 预算为 4 GiB；未知长度输入会按单次上限预留逻辑预算。

## 文件操作

- 覆盖、文件删除和空目录删除默认关闭，只能通过隔离实验配置分别启用。
- 文件删除进入云端回收站并持久记录意图；结果未知时只读对账，不盲目重发删除。
- 非空目录递归删除不支持，服务会拒绝该操作并保留子项。
- 目录移动不支持合并或覆盖已有目标；跨空间移动不支持。
- AppleDouble、扩展属性和 resource fork 不属于产品保证；文件主体内容和当前验收范围内的常见名称必须正确往返。

## macOS 与运行环境

- 推荐入口是 Docker Compose 中的 rclone WebDAV 服务，再使用 macOS 自带 WebDAV 文件系统挂载。
- 原生 FUSE mount 需要本机可用的 FUSE 运行库；构建脚本不会安装驱动或修改系统安全设置。
- 挂载点必须位于项目目录和 Docker bind mount 之外。
- access token、user token 和配置文件必须按私有凭据保护，不得写入日志、证据或版本库。
