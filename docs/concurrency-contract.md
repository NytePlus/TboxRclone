# 单客户端并发约束

2026-09-17 用户明确调整产品范围：不要求解决同一文件的多客户端并发访问；受控客户端内的冲突访问应直接拒绝。此文定义新的目标契约，不表示代码已经实现或验收通过。

## 使用边界

一个挂载根只由一个 TboxRclone 服务实例管理。该实例内可以并行传输不同文件，同一上传会话内可以并行传输不同分片。Finder、应用、CLI 和 WebDAV 的访问必须经过这个实例的统一访问控制；禁止另起独立 rclone 写进程绕过它。

挂载使用及未完成操作恢复期间，不得通过网页、官方同步客户端、另一台电脑或共享协作者修改同一挂载根。其他根不受此限制。切换写入端前必须停止接收新操作，完成或明确处置所有未决操作，再卸载并退出服务。仅关闭窗口、断网或杀进程不代表交接完成。

外部客户端不受本地锁控制，无法保证检测并拒绝它们。外部修改属于违反使用前提；能发现身份或内容变化时必须报冲突并保留本地数据，但不承诺跨客户端防丢更新。这项限制必须在启用写入时明确展示，不能称为云端分布式锁。

## 受控实例必须实现的规则

| 访问组合 | 要求 |
|---|---|
| 同一文件的多个只读句柄 | 允许；每个读句柄绑定内容版本，禁止混合版本字节 |
| 同一文件读与写、写与写、写与删除/移动 | 冲突操作立即返回明确忙/冲突错误，不排队后悄悄覆盖 |
| 不同文件上传或读取 | 允许并行，受全局内存、请求数、缓存容量限制 |
| 同一上传会话的不同分片 | 允许并行；它们属于同一个文件操作，不重复竞争文件锁 |
| 移动/复制 | 在操作前一次取得所需源/目标访问权；移动锁源和目标，复制读锁源、写锁目标；失败不得只执行半边 |
| 目录删除/移动与子项操作 | 目录变更与整棵子树冲突；检查空目录到删除期间阻止子项创建。不同子文件写入不能因共享父目录而全部互斥 |
| 网络中断、取消、结果未知 | 已接受的数据保留；未对账的路径继续保留占用，禁止新的修改或同路径重建 |
| 服务重启 | 先取得实例排他锁，再读取持久日志恢复路径占用；恢复完成前不开放受影响路径写入 |

路径身份使用账户、空间及绝对远端路径，不依赖 remote 别名。重叠挂载根及不同配置指向同一根必须防止绕过；规范化、大小写、Unicode 和路径别名按已验证的名称语义处理，不能擅自把不同远端对象合并。产品入口应固定一个管理根及状态目录，并对第二个实例启动失败；不同状态目录也不能成为支持的绕过方式。

严格 WebDAV 模式拒绝源与目标规范化后相同或互为祖先的 COPY/MOVE；不同兄弟路径仍允许。配置 URL 前缀时，Destination 与已由路由器去除前缀的请求路径必须转换为同一命名空间后再取得占用，前缀外目的地址拒绝。此边界已有离线请求/真实本地 HTTP 回归，尚不表示 Finder 全部场景通过。

占用从接受文件操作前开始，覆盖本地缓存、完整 spool、上传、确认及结果核对全过程。读占用保持到句柄关闭；写占用不能仅保护一个 HTTP 请求或一个分片。失败的第二个操作不得修改远端或清除第一个操作的恢复数据。前端已接受的缓存内容也必须保留并明确显示失败。

同一个已打开文件的多次 write、分片传输及续传属于同一操作。Finder 的顺序“创建空文件→写入内容→关闭”必须支持，不能把自己的顺序写入误判为第二个并发写入者。应用安全保存中的临时文件和重命名仍须满足源/目标规则。

## 仍然必需的正确性

这项范围调整解除“必须支持跨客户端 CAS”的前提，但不解除覆盖发布、丢响应对账、Ctrl+C、SIGKILL、重启、缓存持久化和非空目录保护要求。不允许先删除旧文件再上传新文件；提交/删除结果未知时不得盲目重放，也不得提前释放路径给下一次操作。客户端独占不证明服务端提交具备掉电原子性，仍需实验和明确保证边界。

## 验收调整和当前差距

C-006 改验客户端拒绝同路径冲突，包括读写、双写、第二服务实例及重启恢复占用。C-011 的检查后创建竞态与 C-017 的删除结果未知后重建，均通过受控实例发起并要求拒绝。C-009 保留外部版本变化的防御性读取测试，不能据此宣称支持外部并发写。C-018 仍要求不同文件及分片并行的正确性和效率。

历史服务端 CAS 实验、失败记录原样保留；所有新的分支需要重新执行，不能沿用原证据标 PASS。目前已加入后端进程内文件读写占用：按远端账户/空间/完整路径共享，双写与读写冲突在消费输入前拒绝，读占用保持至句柄 Close，不同 remote 名称或状态目录不能绕过。日志目录现允许持有路径占用的不同文件并行，保留已有 pending 保护，详见末尾补充。

这还不是完整产品访问控制：VFS 可能合并或缓存多个前端文件句柄，后端锁不能区分所有 Finder 写入者。后续已实现的实例排他、目录子树占用及实验性覆盖/删除见下文；完整前端句柄生命周期和重启恢复仍需验收。不得仅凭后端竞态测试把 C-006 标 PASS。

同一持久状态目录内，后端读取现已检查未决日志：即使进程内没有原写占用，也拒绝读取未决路径；其他文件不会等待上传的全局日志锁。该检查与已有 Prepare 的 pending 拒绝共同保护已记录上传。它不覆盖绕过原状态目录、VFS 已缓存数据、尚未写入日志的前端缓存或未实现的目录变更；这些仍属于后续恢复与实例控制工作。

已实现同一 state_dir 的进程生命周期锁：NewFs 在远端查询前取得 instance.lock，恢复命令的 resume/reconcile/abort 同样取得该锁；独立进程失败退出，同进程的多个 Fs 可以复用。必须先停止服务再运行外部恢复命令。锁不在单个 Fs 关闭或无序退出回调中释放，由进程结束时的内核释放，避免关闭过程中的重叠所有者；锁文件不删除，未决日志不清理。已在 Docker/Linux 及原生 macOS 子进程测试正常退出与 SIGKILL 接管。不同 state_dir、不同机器及旧版进程尚不能由该锁排除；需统一管理入口才能满足完整第二实例验收。

进一步增加共享 `ownership_dir`：按 endpoint/library/space 的摘要建立空间级进程锁，并持久绑定原 state_dir。这样在共享注册目录内，切换状态目录既不能绕过活跃实例，也不能在原实例退出后跳过其未决日志。当前绑定整个空间（即使挂载根不重叠），空间内不同文件仍由同一服务处理；不同空间可独立运行。

原生默认注册目录为用户配置目录下的 `TboxRclone/owners`；Compose 服务及故障客户端使用共享 `/state/owners`。独立恢复命令使用相同 `--ownership-dir`，也默认读取 `RCLONE_SJTU_OWNERSHIP_DIR`。所有入口必须使用同一份注册目录、相同 endpoint 和一致的绝对 state_dir 挂载路径；不得通过换用户、换注册目录、换 endpoint 别名或复制状态来启动并行实例。本地锁无法约束其他主机或不参与此协议的旧版客户端。跨宿主/容器不同挂载路径的自动迁移尚未实现；不得删除绑定文件来跳过恢复。


## 实验性顺序覆盖

`lab_writes=true` 且 `lab_overwrite=true` 时，隔离实验根允许顺序覆盖已有文件。默认仍拒绝覆盖。首次新建使用 ask，覆盖的 multipart 初始化和确认使用持久记录的 overwrite 意图；旧日志未记录 overwrite 时仍按 ask 恢复。新内容先完整 spool，再记录旧 ETag/大小，上传完毕后重新核对旧身份，然后提交；不删除旧路径。该核对不是 CAS，依赖无外部写入约束。确认后仍完整下载核对 SHA-256，确认丢响应只读对账。

取消已初始化但尚未提交的覆盖时，只删除上传会话。会话消失后，仅当原路径仍保留旧 ETag/大小才记 Aborted；旧文件缺失或变化则保留 AbortUnknown 和新 spool。提交后的取消仍先对账，不撤销正式文件。

已通过模拟 HTTPS 后端的零字节旧文件→非空内容、确认丢响应、分片失败、提交前取消、目标变化以及取消丢响应测试。真实云盘发布原子性、macOS webdavfs/Finder 保存及全部中断场景尚未验证。不得将此实验开关当成发布许可，VFS 前端冲突控制仍未完成。

## WebDAV 请求入口保护

Compose WebDAV 服务现由 Tbox 自有 guard 暴露公共端口，rclone WebDAV core 只在项目内部网络提供服务。guard 在转发请求前一次取得本次请求所需的路径占用：读者可共存；写入与相同文件访问冲突返回 423；MOVE/DELETE 锁定子树；COPY 读锁源子树、写锁目标子树。公共请求路径和 Destination 都去除同一个 BaseURL 后进入统一命名空间；前缀外目标及源目标重叠在转发前拒绝。源目标取得失败不留下半份占用。目录浏览只占目录本身，允许其他子文件传输；ZIP 下载占整个子树。上游响应结束或转发失败时释放。该规则实现于 `internal/webdavguard`，不修改 rclone 的请求锁逻辑。

guard 同时启用持久化 zero-byte creation barrier：macOS webdavfs 的初始空 PUT、两轮 LOCK/UNLOCK 在公共入口由 guard 处理，避免 core 的 LOCK 创建正式空对象；非空内容 PUT 成功后再发布，不能以第二轮解锁推断空文件完成：真实 Finder 之后仍可能发送内容。占位状态保留至实际 PUT；无内容 PUT 的纯空文件完成语义尚待验证。状态保存在 `.state/webdav-guard`，故障时保留未决状态。

内部 core 固定使用 `--vfs-cache-mode off`；缓存异步写回会超过 guard 的请求生命周期，因此部署配置不允许更换为后台写回模式。guard 仅覆盖同一入口的 HTTP 请求；backend 的路径占用、实例锁和持久日志继续覆盖云端操作及未决恢复。它仍不覆盖原生 FUSE 文件句柄、两个应用在不同请求间交替修改同一文件、跨宿主实例或长期 WebDAV LOCK 语义。这些仍需对应验收，不能把请求并发拒绝当成所有文件句柄并发场景已经完成。

后端目录创建也必须检查每一级路径的未决上传记录。未决文件不能被替换成同名目录，也不能被用作新目录的祖先；初次查询不存在时，在取得路径占用后重新检查，再发送创建请求。已有无冲突目录可供兄弟文件共用。此项已有关闭重开日志及模拟 HTTPS 回归，尚未代替真实 Finder 重启场景。

## 实验性文件删除

显式 `lab_delete=true`（同时需要 lab_writes）允许隔离根内的文件回收站删除。取得文件写占用和日志锁、核对调用对象的旧 ETag/大小后，持久化 kind=delete 和 DeleteSent，才发送一次 `DELETE file?permanent=0`。之后保存 DeleteUnknown 并只读查询路径；独占前提下确认 404 才记 Committed，释放持久占用。查询失败或路径仍存在，保留未决日志；禁止盲目重发 DELETE。tbox-state 的 reconcile 分派删除对账，resume/abort 上传命令拒绝删除日志。

正常返回时尽可能记录 recycledItemId；响应没有 ID 或丢失时不虚构回收站身份。删除的零字节 spool 只是意图凭据，不是原文件备份。真实实验已确认路径删除、后续重建，以及单个生成条目的回收站 ask 冲突拒绝和 rename 恢复。回收站数量、真实删除/恢复丢响应、产品级恢复流程仍是完整验收缺口。空目录删除见下述补充；默认不开启该实验能力。


## 空目录删除

lab_delete 同时允许空目录删除。后端持有子树写占用，阻止子项创建/读写和其他目录操作，并在共享日志锁和独占子树占用下检查本子树的所有未决记录。确认目录类型及完整列表为空后，才写入 kind=rmdir/DeleteSent 并发送一次 directory DELETE（permanent=0、directory_only=1）。结果未知时只读核对；持久 rmdir 记录阻止整个子树的新上传与 Mkdir，终态确认不存在才释放。安全性依赖受控单客户端，directory_only 参数本身不保证非空目录保护。

WebDAV 默认 RemoveAll 会递归删除，所以本项目同时启用 `--no-recursive-delete`：目录走 VFS Remove 而不是 RemoveAll。非空目录拒绝，子文件保留；不能通过先递归删除子项来让 Rmdir 的空检查失去意义。目前不提供 Finder 递归删除非空文件夹；未来若实现，应有单独明确的操作契约和恢复机制。


## 实验性文件移动

后端 `lab_move` 默认关闭，仅用于隔离根中的直接后端实验。移动先一次取得源和目标的写占用，核对源身份，完整备份源内容，再持久化移动意图。首份 Prepared 日志已经包含 kind=move、源路径、目标路径及覆盖策略；即使日志发布后目录 fsync 失败，也不会被当作上传续传。准备阶段未发送移动，显式 reconcile 可记 Aborted 并释放两个路径，备份保留。

MoveSent 持久化后只发送一次请求。无论应答是否送达，均要求源路径不存在、目标完整下载的大小与 SHA-256 等于本地备份才记 Committed；否则两个路径继续被未决日志占用，禁止重放移动。源被重建、目标错误、服务端拒绝均保留备份与未决状态。未决移动也阻止父目录删除。当前备份只覆盖源内容，不是目标旧版本备份，也不证明服务端覆盖发布的掉电原子性。

模拟 HTTPS 测试覆盖成功、响应丢失、源重建、目标错误、拒绝、已有目标拒绝/显式覆盖，以及双路径占用取得失败不泄漏。日志测试注入首份记录发布后的目录同步失败；准备态恢复不访问云端。Docker Compose 的完整 Go race 测试与 vet 已通过，但不是 Finder/System PASS。

rclone 通用层与 x/net/webdav 原先均在调用后端 Move 前删除已有目标，回归已复现此丢失窗口。新增默认 false 的通用 MoveOverwrites 能力：声明此能力时，operations.Move 和 WebDAV 的 MOVE 目标处理均交由后端直接替换，不先删除；其他后端维持原行为。Overwrite:F 仍拒绝已有目标，目录覆盖不借用文件能力。SJTU 在 lab_move 开启时声明此能力。

目录移动已补上整树备份与单次请求，见下节。已有目标拒绝合并/覆盖；通用 NoDirMoveFallback 标记阻止错误后逐文件回退，保留标准 ErrorDirExists。Compose 新增 TBOX_LAB_MOVE 显式开关；隔离服务已用于真实文件移动实验。覆盖移动204、移到空目标201、Overwrite:F拒绝412以及独立云端内容/源缺失核对均通过，两个移动日志 Committed，见 [文件移动证据](evidence/2026-09-17/webdav-file-move.json)。

原生 macOS 挂载检查确认是 webdavfs 后，另一次实验在创建目标文件时超时，尚未执行 rename；同期 Docker API500、随后 daemon 不可连接。源内容和空目标已有 Committed 日志，测试文件保留，见 [原生失败证据](evidence/2026-09-17/native-move-blocked.json)。原因未定，不能把协议成功当作原生/Finder移动成功；真实移动丢响应与进程中断恢复仍需验收。


## 实验性目录移动

lab_move 同时开放同账户/空间、同 state_dir 的目录专用移动。一次取得源和目标整棵子树的写占用，核对未决子项、源类型、目标不存在及源目标不重叠。完整读取源文件（绑定ETag），连同零字节文件、空目录写入本地tar；只存内容和相对路径，不将归档解压到任意路径。整个归档计入max_upload上限，含tar开销；备份失败或超限不发送移动。第一份Prepared日志已是kind=dirmove并包含源/目标子树，避免重启误作上传。

MoveSent落盘后只发送一次PUT directory，策略ask。结果未知只读对账：源必须404，目标的完整目录树必须与本地备份的路径、类型、大小和逐文件SHA-256完全一致，额外路径或缺失空目录都拒绝成功。未决日志阻止两棵子树及其后代的新建、写入和读取/列目录。未发送的Prepared可显式reconcile到Aborted，保留tar；提交结果未知不重发请求，也不逐文件搬运。

新增通用NoDirMoveFallback能力，SJTU显式设置；默认后端仍保持上游行为。已有目标（包括同一路径）返回标准ErrorDirExists，operations.DirMove直接返回错误。目录覆盖/合并尚未实现；跨空间移动也不支持。归档保留源内容，但完整系统验收还需要元数据、回收策略、效率和所有故障点验证。

真实WebDAV正常移动、目录移动后丢响应、取消及独立后端进程SIGKILL接管均通过；后两者分别保留MoveUnknown/MoveSent和双子树占用，对账后Committed。源备份包含文件内容、零字节文件和空目录。证据见[正常移动](evidence/2026-09-17/webdav-directory-move.json)、[丢响应与取消](evidence/2026-09-17/directory-move-response-loss.json)、[SIGKILL](evidence/2026-09-17/directory-move-process-death.json)。这些不是整机掉电或Finder系统PASS。

目录移到目标 Fs 的根（dstRemote 为空）时，只创建编码后目标路径的父目录；不能调用 Mkdir("") 再次获取已由该移动持有的目标子树锁。上游完整套件暴露了此自冲突，新增跨 Fs 根目标回归先复现失败再修复。它不放宽其他操作的冲突拒绝规则。


## 不同文件并行与容量限制

后端持有空间级实例所有权和全部受影响路径占用后，使用共享日志 flock；每个操作独立创建 spool、记录和临时文件，单条记录仅一个写者，原子 rename 与目录 fsync 保持不变。目录变更仍独占子树，移动仍一次占用源和目标。独立恢复工具仍使用独占 flock；任何活跃共享操作都阻止它进入，恢复的独占锁也阻止新操作进入。进程退出/SIGKILL 由内核释放 flock，持久未决记录仍阻止冲突路径。

每个空间最多 4 个活跃变更，名额覆盖完整 spool/源备份、上传、提交和对账；每个上传最多 4 个分片 worker。不同文件等待容量时可取消，同路径第二个操作在等待容量之前立即拒绝。该限制不等于 spool 总磁盘配额或历史备份 GC，后两者仍需实现与验收。

双文件数据面屏障回归在旧独占锁下失败、共享锁下通过；同时验证同路径拒绝、完整内容和两条 Committed 日志。`TestDifferentFileWritesMayRunInParallel` 还验证 WebDAV guard 的两个不同路径写请求可以同时进入上游。真实两个 9,900,000 字节文件使用两个上传会话并行，独立云端下载 SHA-256 和本地 spool 均匹配，见 [证据](evidence/2026-09-17/parallel-uploads.json)。数据请求入口含同步屏障，因此记录耗时不能当无干预吞吐基准；C-018 的 Finder 交互、p95、限速丢包和完整资源指标仍未通过。

## 并行文件共用新父目录

不同文件的 Put 可能同时需要同一个尚不存在的父目录。现在按账户/空间及编码后路径共享正在进行的 mkdir 检查/创建，只有一个所有者执行请求，其余相同的 ensure 等待同一次结果。只合并相同的幂等建目录需求，不合并文件写入或目录删除/移动。所有者仍持有原有路径占用，所以其他类型的冲突立即拒绝；一个等待者取消不会取消原始创建。失败和结果未知原样返回所有等待者，不自动重放 PUT，不把丢响应当作成功。

已有目录同样仅共享短暂的存在性检查，不在上传数据期间持有公共父目录写锁。创建飞行记录在完成后删除，后续显式请求重新检查远端，不能把进程内完成缓存当成持久事实。创建者自身取消时，加入者也获得该次失败，可由调用者决定后续操作；这里不增加云端 mkdir 的事务/掉电保证。
